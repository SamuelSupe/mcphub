1. 向管理员获取接入信息

需要的信息示例或说明
MCPHub 完整地址https://hub.example.com/mcp，包含路径。
CLI client ID例如 mcpbridge。它是管理员登记的登录应用标识，不是后面生成的 ci_… 客户端入口 ID。
访问资格你的公司账号已启用，并有目标服务和工具权限。
回调端口仅在管理员要求固定端口时需要，例如 8765。

2. 安装本机连接器

按操作系统和 CPU 架构下载 mcpbridge，核对校验值并解压。具体步骤见 安装与升级。确保 AI 客户端可以运行它；后续向导会使用连接器的实际绝对路径。

3. 在使用 AI 客户端的电脑上运行向导

mcpbridge setup --server https://hub.example.com/mcp --client-id mcphub-cli --profile work > mcphub-mcp.json

work 是本机连接配置的名称，你可以自行命名。已有该 profile 的登录信息时，使用 mcpbridge setup --profile work > mcphub-mcp.json。固定回调端口可追加 --callback-port 8765。

  1. 浏览器打开后，使用公司账号登录。
  2. 回到终端，从向导列出的服务中选择一个，再选择具体工具编号。服务和工具的选择在终端中完成。
  3. 按需要设置资源条件、授权时长和客户端名称。第一次使用可先选择所需的只读工具。写入或未分类工具需要额外确认。
  4. 选择配置格式：Codex 需转换为 TOML；Claude Code 等可先选通用 JSON；VS Code 可选专用 servers JSON。
  5. 按终端提示打开授权页，核对浏览器与终端的配对码、目标服务、工具和数据范围，点击「确认授权」。
目录显示工具，不代表已经获得调用权限必须完成浏览器确认。工具选择为空时，不会自动授予全部工具。一个客户端入口连接一个服务；多个服务需要分别运行向导。

4. 将生成配置加入 AI 客户端

打开 mcphub-mcp.json，保留实际生成的 command、args 和存在时的 env.MCPHUB_HOME。将条目合并到现有客户端配置，再重新加载 MCP 连接。向导不会修改或覆盖客户端自己的配置文件。

根据客户端选择 Codex、Claude Code 或 VS Code 的具体步骤。

5. 确认连接成功

客户端应显示刚才授权的工具。再用生成配置里的实际客户端 ID 检查：

mcpbridge doctor --profile work --client ci_example

向导和诊断只验证连接、授权状态与工具目录，不会执行工具。若提示需要个人账号，到 个人授权中心连接账号 后重试。若向导在授权后诊断失败，配置仍可能已经生成；保留它并按提示排查。

接下来怎么用

从一个明确、只读的任务开始，例如让 Agent 查找你有权访问的项目资料。查看 使用工具与数据；需要改动数据时，先了解 写操作审批。

请在同一电脑、同一系统账号下运行向导和 AI 客户端。SSH、容器或远程开发环境不能直接复用本机路径和连接服务，见 多服务与多环境。
