从明确的只读任务开始

先让 Agent 查看工具，再描述具体目标和数据范围，例如「使用已授权的查询工具，查找项目 A 本周任务，只读取资料」。工具名以客户端实际目录为准。

  1. 确认服务和工具。
  2. 明确项目、资源标识或查询范围。
  3. 阅读结果，确认数据对应自己的任务。
  4. 修改数据时按 写操作审批 独立确认。

为什么只看到部分工具

目录受公司发布状态、身份权限和客户端授权共同限制。向导是可申请目录；客户端是实际授权目录。新增工具不会自动扩大已有授权，需要重新确认。

通过 MCPHub 权限检查不保证业务系统允许操作。个人账号的上游角色、资源权限和账号状态仍影响结果。

工具、提示词、资源和订阅

能力用途与条件
工具 Tools查询或业务操作；向导主要配置此能力。
提示词 Prompts服务提示模板，需服务和客户端支持，并显式授权。
资源 Resources读取服务暴露的资料或上下文，需单独启用。
订阅 Subscriptions接收资源变更通知，需同时启用 resources 和 subscriptions。

额外能力见 命令参考。工具参数资源条件不能作为资源 URI 或提示词的访问限制。

失败与结果不确定

连接器不会因网络失败自动重放操作。查询可确认原因后重试；写入应先检查审批和业务状态，避免重复执行。429 时等待额度恢复，写请求仍需确认是否已接纳。

批准、执行和成功是不同阶段浏览器批准只允许继续。原客户端恢复调用、上游接受操作、业务完成需要分别确认。

查询一次调用

保留请求 ID、发生时间、服务和工具名；未显示 ID 时提供时间范围和任务说明，交给管理员查询诊断。不要发送凭证文件。
