# 实现审计与本地修复记录

日期：2026-10-02。对应 v2.3.0。以下记录发布前的实现审计、修复和实际验收范围。

## 范围与结论

检查了内建账号、MFA、组权限、LDAP/OIDC 配置更新、Token 签发与刷新、设备配对、ClientGrant、MCP 请求校验及 MCPBridge 的 Agent 交互链。重点核对凭证交付、撤销、并发、持久化和调用性能。未发现可复现的 P0；以下 P1 边界和性能问题已修复。结论限于这些代码路径和列出的实际验证，不代表长期负载或所有外部 Agent 已验收。

## 已修复问题

| 优先级 | 可复现问题 | 修复及回归保护 |
| --- | --- | --- |
| P1 | 已完成配对的 Grant 撤销后，旧私有配对码仍可取消并删除已交付的 SSO 家族；其他客户端可能共用该家族 | 完成状态永久失去取消交付会话的权限；SQLite、PostgreSQL 的双 Store 流程验证撤销 Grant 后旧码仍被拒绝，SSO 家族保留 |
| P1 | 浏览器确认后，Grant 或 Broker 会话先到期，领取入口仍会签发新登录凭证 | 在领取事务内检查 Grant 状态、授权期限、申请期限以及 Broker 有效性；到期用例必须拒绝交付 |
| P1 可用性 | 密码散列期间持有身份全局锁及数据库事务，未存在账号的并发登录也能阻塞所有用户的权限读取和调用接纳 | 散列移到锁外；锁内重新读取密码散列、账号状态、失败计数和 TOTP 计数。已有重置、停用、锁定测试及新增并发 TOTP 用例保护安全语义 |
| P2 | 每个交互式业务调用前重复查询授权配置、当前 Grant、可选目录和 MCP 工具目录，并串行等待这些网络请求 | 复用已连接的 MCP 会话；服务端仍对每个请求校验实时身份、Grant、工具、资源限制和审批。集成测试计数确认业务调用不发额外授权查询，且撤权后的直接调用失败 |
| P2 | 本地配对文件临时读失败会用空状态覆盖待确认申请，后续 start 产生新申请 | 保留原请求和状态；实际暂时移走私有文件，再恢复，验证请求 ID 不变且可继续确认 |
| P2 | 旧远端调用延迟失败可能关闭已替换的新连接 | 仅在失败连接仍是当前连接时关闭它；取消的调用继续直接返回取消结果 |
| P1 发布风险 | 本地候选包使用 Go 1.26.0；源码扫描工具自动切到 Go 1.26.8，掩盖了候选二进制的旧标准库安全问题 | 将 `go.mod` 最低版本和容器构建固定为 Go 1.26.8；CI 与发行流程新增可达漏洞扫描，最终包另核对构建工具链 |

## 发布前第二轮复核

再次核对账号重置/停用、组授权、最后管理员保护、企业身份来源变更、设备凭证一次性交付、客户端本地凭证保存和 OAuth 刷新。未发现新的可复现应用层 P0/P1；构建工具链风险如上已修复。

旧候选包的二进制扫描提示了旧标准库风险。Go 官方记录确认此前多个补丁修复了 TLS、证书、HTTP、URL 等安全问题，见 [Go 发行记录](https://go.dev/doc/devel/release#go1.26.8)。源码可达扫描在 Go 1.26.8 下为 0；`golang.org/x/crypto/openpgp` 的模块级告警不涉及当前导入的包，项目仅使用受维护的密码学包。剥离符号的二进制扫描可能按整个模块保守报告，因此发行检查同时使用源码可达扫描与包内真实构建版本，不能只看扫描工具自身的 Go 版本。

## Ponytail 整理

- 组权限由逐组查询改为一次批量查询；按原成员顺序合并，保留权限版本、同来源限制及缺失组拒绝行为。
- 身份服务更新一次扫描 SSO 家族，批量处理受影响用户；不再为每个用户重复扫描所有会话。回归验证多个 LDAP 用户均失效，同时 OIDC 用户仍可使用原会话。
- 共享会话撤销逻辑放回会话模块；公共 endpoint 策略查询复用已有事务版本，删除重复实现。
- 工具目录增删使用名字集合，避免两轮嵌套扫描；设备 Grant 查询在 SQLite、PostgreSQL 都使用索引。
- 合并重复成功分支。没有引入缓存、新依赖、独立认证层或迁移流程。

## 实测性能

OrbStack Ubuntu / Linux arm64，同一台机器、同一数据库驱动和散列参数。执行 `BenchmarkEffectiveIdentity`，每种场景重复三次，每次测量 1 秒；以下为中位数，属于小范围延迟测量，不是容量或长期压测结果。

| 场景 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 单组、无登录负载 | 0.0379 ms | 0.0410 ms |
| 单组、4 个并发未知账号密码校验 | 173.642 ms | 0.0475 ms |
| 64 个组、无登录负载 | 1.390 ms | 0.733 ms |
| 一个已授权业务调用的额外授权查询 | 3 次 | 0 次 |

单组空闲场景未显示收益；本次优化解决密码散列造成的全局阻塞和多组查询成本，不宣称所有调用吞吐都有相同比例改善。密码散列仍使用 Argon2id 19 MiB、2 次迭代、1 lane，登录入口保留 4 个并发散列上限。

复现命令：

```sh
go test ./internal/configstore -run '^$' -bench BenchmarkEffectiveIdentity -benchtime=1s -count=3
go test ./internal/client -run TestDevicePairAndInteractiveAgent -count=1
```

## 验证记录

- OrbStack 中全量 `go test ./...` 和 `go vet ./...` 通过。
- `configstore`、`client`、`app`、`sso`、`hub` 的竞态检查通过。
- 真实 PostgreSQL 生命周期与两个独立 Store 的并发交付检查通过；SQLite 使用相同关键行为测试。新增并发 TOTP 用例在两种数据库上都只接受一次。
- 双语文档站生成 84 个页面，检查 3422 个本地链接和资源通过；Chrome 核对了新配对说明及中英文页面切换，未发现控制台警告或错误。
- 实际解压的 Linux arm64 候选包通过六个 YAML 校验、四个默认模板的启动、重启和管理员登录。源配置、包内配置和文档站模板逐字一致；未设置 PRIMARY 变量或外部 issuer。
- 本机 Chrome 完成 OIDC 登录、返回同一申请、工具默认不勾选、空工具选择被阻止、明确授权及中英文结果检查，控制台未发现警告或错误。真实 stdio Agent 使用 `2025-11-25` 完成认证前初始化、动态工具通知、获准读取和撤销后的工具移除，公开输出无私有凭证。
- Chrome 使用隔离 HTTP 预览代理转换测试回调和 Cookie；Agent 到网关使用 HTTPS 并校验测试 CA。没有绕过浏览器证书警告；这不是生产 TLS 验收，也没有安装到真实 Codex、Claude Code 或 VS Code 的客户端 UI。此前完整验收范围见 [设备配对验收记录](mcpbridge-device-authorization-validation.zh-CN.md)。

## 保留的容量边界

SQLite 使用单连接，PostgreSQL 元数据写事务使用全局 advisory lock，保留跨表命名、版本和安全状态的原子性。本次将昂贵密码散列移出了这些锁；未在没有负载证据时拆掉事务保护。大量账号同时更新配置、刷新凭证或进行配对时，仍需真实负载测量，确认写入争用后再考虑按资源加锁。

账号密码重置仍需扫描 SSO 家族；企业来源更新已避免逐用户重复扫描。工具调用的实时权限读取没有缓存，撤权语义保持即时。未做生产身份服务、生产 TLS 证书、长时间运行和跨机器容量测试。
