# 三批产品架构改进验收记录

日期：2026-10-03。范围为新部署、单实例 MCPHub；不包含旧配置、变量或数据库迁移。本文记录 v2.4.0 实现与本地验收，发行包和线上文档交付以 [GitHub Release](https://github.com/SamuelSupe/mcphub/releases/tag/v2.4.0) 及其发布检查为准。

## 已实现

| 批次 | 交付行为 |
| --- | --- |
| 身份与权限 | 独立权限组、LDAP/OIDC 组织组的显式映射、按所选能力保存 Scope 快照、有效权限来源、企业组验证有效期；账号身份仍按来源和稳定 ID 隔离。 |
| 服务与 Agent 接入 | MCP / HTTP 统一服务入口；标准 OAuth + PKCE 登录与双语同意页面；一次连接选择多个服务，各服务独立授权、撤销；OAuth 客户端 UI 注册。MCPBridge 使用标准 Bearer，无需自定义 Grant Header。 |
| 配置与运维 | 加密配置草稿、校验、影响预览、审批与应用、创建回退草稿；运维中心显示配置来源、版本、目录验证、备份和恢复状态；一致性备份、校验和、隔离恢复检查与空目标恢复命令。 |

继续复用原有管理 API、服务编辑器、审批和设备授权。直接 API 写入保留现有契约；管理台主要配置编辑先生成草稿。回退重新检查当前版本，不恢复已撤销的会话或授权。

帮助入口：[管理员手册](admin-guide.zh-CN.md)、[组与权限](builtin-accounts.zh-CN.md#组与权限)、[LDAP / OIDC](enterprise-login.zh-CN.md)、[用户接入](user-guide.zh-CN.md)。英文对应文件同步更新。

## 实际运行验证

Linux 后端使用 OrbStack Ubuntu / Go 1.26.8。PostgreSQL 17 和 OpenLDAP 在 OrbStack 容器中运行；管理台和浏览器 OAuth 流程使用本机 Chrome。所有账号、证书、凭证和数据均来自本轮独立测试实例。

| 场景 | 结果与证据 |
| --- | --- |
| 默认模板 | 未设置两个 `PRIMARY` 变量或 `MCPHUB_AUTH_ISSUER`，仅使用公开地址和配置密钥，`validate` 成功；新实例正常启动并打开管理台。 |
| 企业身份 | 实际 LDAPS 用户绑定和 OIDC 签名登录成功；两个来源的同名 engineering 组保持隔离，通过明确映射继承同一个权限组。 |
| 权限 UI | Chrome 核对组织组状态与独立权限组的不同编辑入口、两个组织组映射和有效权限来源；选择/取消工具时 Scope 预览对应变化。 |
| 配置流程 | Chrome 完成服务编辑、脱敏草稿预览、校验、应用；从历史配置创建回退草稿，再校验并应用，版本递增。 |
| 标准 OAuth | Chrome 完成登录、选择两个服务、确认授权、返回 MCPBridge loopback 回调成功页；终端确认登录完成。内建客户端与 UI 注册的客户端均完成登录。 |
| Agent 调用 | Linux MCPBridge 实际 stdio Agent 会话调用两个 MCP 服务，各自使用不同后端密钥；撤销 Alpha 后 Alpha 拒绝，Beta 在同一 Agent 会话继续成功。Agent 输出不含凭证。 |
| 备份与恢复 | 实际运行 `backup`、`verify-backup`、`restore`，恢复到独立空 SQLite 目标；源实例的现有 Beta 授权不受影响。 |
| 恢复后业务 | 启动恢复副本，旧访问凭证返回 401；原用户密码、权限映射、OAuth 注册和两个加密后端凭证保留。重新登录并同意授权后，两服务实际读取成功。 |
| 运维 UI | Chrome 显示恢复时间和“原有会话与授权已撤销”，请求记录写入失败为 0；中英文导航与运维界面检查通过。 |
| PostgreSQL | 实际 PostgreSQL 配置生命周期及备份恢复测试通过，涵盖持久化、事务与恢复后的安全状态。 |

浏览器使用独立预览代理访问本轮测试服务，实际 MCP / OIDC / LDAP 网络连接保留 TLS 校验；未修改系统证书信任或绕过 Chrome 证书警告。

## 自动验证与回归保护

- `go test ./...`、`go vet ./...`：通过。
- `go test -race ./...`：最终代码带实际 PostgreSQL / Vault 全量通过；退出边界回归与原有限流测试额外连续运行三轮通过。
- `node --test internal/app/testdata/adminui-i18n.test.mjs`：5 / 5 通过，包含全部管理台模块的浏览器语法检查。
- `node docs-site/build.mjs`：生成 84 个中英文页面，3448 个本地链接和资源校验通过。
- `git diff --check`：通过。

新增或扩展的回归保护针对实际边界：同名身份隔离与映射撤销、企业组过期、PKCE 多服务授权、单服务撤销不取消其他服务在途请求、OAuth 客户端变更撤销凭证、初始客户端注册版本 0、配置冲突与回退、恢复撤销旧安全状态、错误密钥/篡改备份/非空目标拒绝。Chrome 验收发现的重复模块绑定和 CSP 阻止合法 loopback 回调均已修复并补充检查。

## UI/UX 后续验收

本机 Chrome 检查中英文管理台、个人门户与设备授权页，包括桌面及 390 × 844 移动视口。设备语言切换保留服务、工具、时长与资源选择；失效授权码可原页替换；非法资源条件返回可处理错误且申请仍可批准。实际 MCPBridge 配对完成，获选只读工具调用成功，越界资源被拒绝。账号安全对话框将密码与 MFA 分开，错误密码后保留验证器信息，重新设置及 Escape 关闭正常。审批取消、语言切换、确认/MFA 门禁与拒绝结果经过交互检查。本轮未通过 UI 修改正式密码或启用 MFA，未实际执行审批后的生产写入。

发布前全量竞态检查发现应用关闭未等待旧运行实例和后台连接循环结束，导致后一测试修改全局 HTTP transport 时与前一测试连接退出冲突。关闭流程现在等待后台连接与旧实例退出；新增回归覆盖关闭前已退役实例仍有请求的边界。限流测试继续使用原有 HTTPS 服务和完整行为。

## 验证边界

本轮验证不代表容量、长时间压力或多实例一致性验收。未新增 SCIM、SAML、同类多条身份连接、LDAP 轮询或迁移流程；未进行真实企业身份平台、生产 Vault 或全部第三方 MCP 客户端兼容性验收。发行流程先生成草稿包，检查全部平台的包清单、工具链、校验和与源配置一致性，再从实际下载的发行包验收安装后公开发布。包内配置与 GitHub Pages 的同名模板必须逐字一致。
